# Fusion 0.13 validation

Candidate: 0.13.0. Validation date: 2026-11-04.

## Scope and boundaries

The candidate keeps Pi as terminal/host owner and pi-subagents as native child
owner. No personal credentials, package configuration, or provider settings are
changed by validation. Automated and TUI flows use real Pi/native subagents with
a localhost deterministic model fixture. Webfox uses its real custom-provider
command adapter without external network calls. This verifies integration and
presentation, not answer quality or live vendor availability.

## Automated gates

The full lint/types/test/package gate passed: 46 files, 546 tests on Node
24.15.0 and minimum Node 22.19.0. Audit reported zero known vulnerabilities.
Documentation links, actionlint and offline zizmor passed. Independent review's
unknown-cost-provenance finding was fixed and regression-tested.
The suite covers:

- Select, merge, single, rolling refill after authentication failure and partial
  coverage, exact final synthesis sentinels beyond native preview limits.
- Unsupported explicit lifetime rejection before native spawn; model schemas do
  not offer it and reject extra arguments.
- Configured Webfox child tools and explicit missing-child-tool failure.
- Consumed result artifacts, retained workflow values, queued completion events,
  unrelated completion IDs, running roots with temporarily finished child rosters.
- Bounded missing-output reconciliation with no model retry.
- Stop delivery versus native tracked-run retirement, wrong IDs, unknown proof,
  failed delivery, no resumable-interrupt fallback, owner-exit/reload quarantine.
- Project trust and bundled mutation-capable concurrency refusal.
- Native wake receipts, abort suppression until explicit input, inheritance and
  observed usage/provenance, known zero versus missing cost.
- Width/Unicode/theme/resize rendering, complete expanded output and unchanged
  caller/model report content.
- Hermetic process bootstrap/close, real Git candidate identity/drift and
  cancellation, durable admission and cross-process replay fences.

The test harness compiles workers once and reaps them explicitly. Git templates
are prepared once and copied into disposable repositories. Real Git setup runs
in hooks. Git-context integration cases have a 20-second harness budget because
the production verification command alone allows 10 seconds; pure unit tests
retain the five-second default. This is not a Fusion/provider deadline change.
Two workers cap concurrent native imports/filesystem work. No assertions or
failure paths are skipped.

## Real Pi in agterm

A dedicated agterm window/session runs `scripts/validate-pi.ts`, not a mock TUI.
The harness copies bundled read-only agent prompts into an isolated agent
directory, sets native autoResume false before host startup, runs real Pi and
pi-subagents, and retains native/Fusion records and hook metadata.

Observed:

- Doctor, merge and partial-coverage reports render in the real TUI.
- Configured expansion works. A 780×640 window renders wrapped Unicode content
  without clipping; wide layout and native footer remain intact.
- Ordinary cancellation persists requested → delivered → cancelled, with
  native tracked-run proof before terminal admission release.
- Regular and fullscreen sessions used the candidate. Doctor executed with a
  single Enter; real profile completion replaced `--profile m` with `--profile
  merge`. Exact-match completions no longer swallow command execution.
- A native idle report probe invoked `before_agent_start` with
  `messageType: custom`, `customType: fusion-report`; no synthetic user prompt.
  Normal named-profile review and partial coverage completed in the real TUI.
- Reload during a bound slow panel preserved the same review/native ID in
  `runtime-replaced` quarantine. Replacement launch was refused.
- An owned fixture Pi host was verified by parent PID and working directory,
  killed with SIGKILL, and reopened. The same review/native ID persisted in
  `owner-exited` quarantine, with no successor workflow or synthesis launch.
- Queue progress displayed `0/3 done, 2 running, 1 queued` during rolling work.
- Stop testing also reproduced the native `writer-close-unverified` limit:
  stopped runners alone did not release admission. The operator explicitly
  approved release with this fail-closed limit, diagnostics and no automatic
  reset. Native fixture child lifecycles were terminal after the checks.
- The native CLI generated a standalone HTML export. Browser rendering and
  live paid-provider answer quality are not claimed tested.

Screenshots and session evidence are retained locally outside the npm tarball.
No screenshots of unrelated windows or private credentials are published.

## Deliberate limits

- Native retirement can remain unknown after accepted stop. Cancellation then
  remains pending indefinitely, with the native reason visible. There is no
  automatic reset or PID-absence inference.
- Native RPC cannot report an already-running owner's effective autoResume.
  The configured prerequisite is checked, and operators must restart after
  changing it. Fusion never silently edits that global setting.
- Neither backward ancestry nor an old source proof fences future successors.
  Runtime-replaced/owner-exited reviews remain quarantined without replay.
- Ordinary native tracked-run proof is not an escaped-descendant kernel
  guarantee. Strong lifetime mode remains controller-only and capability gated
  for a custom runtime; published pi-subagents does not implement it.
- Independent thinking-only overrides cannot be forwarded by the public async
  RPC. Existing settings warn; new defaults inherit native model/effort.
- No unreleased breaking dependency or live paid provider is claimed tested.

## Final release gate

Run `npm run test:all`, `npm audit --audit-level=moderate`, documentation link
checks, actionlint and zizmor. CI requires locked Node 22.19/24 plus latest-allowed
dependencies on Node 24. Publish only through the existing tag workflow after
those checks pass. The GitHub release and workflow logs are the external
publication record; local TUI evidence stays outside the npm package.
